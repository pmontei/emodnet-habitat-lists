# emodnet-habitat-lists

Habitat classification systems, the crosswalks between them, and the thematic lists used to select
the habitats that go into each **composite data product** of EMODnet Seabed Habitats, Work
Package 3 (CCMAR).

The repository separates two kinds of reference:

* **Classifications** — typologies in which maps and points are classified directly (EUNIS, HELCOM
  HUB, Barcelona Convention, JNCC Marine Habitat Classification, Habitats Directive Annex I, OSPAR,
  ICES VME, Ramsar, IUCN GET, map classes of the Allen Coral Atlas and Global Mangrove Watch…).
  Stored in `systems`, `habitats` and `crosswalks`.
* **Lists** — selections, groupings or functions defined on top of one or more classifications:
  GOOS Essential Ocean Variables, the marine groups of the Nature Restoration Regulation, EMODnet
  biogenic substrate, coralligenous, Essential Fish Habitat… Nobody classifies a map "in" a list;
  habitats are selected for it. A list has items (its categories, with definitions) and members
  (the habitats of any classification linked to each item). Stored in `lists`, `list_items` and
  `list_members`.

Essential Fish Habitat is a list of a different nature: it describes the functional importance of
an area or habitat for a species at a life stage (spawning, nursery, feeding, migration). EFH
products are built by combining EFH maps per species and life stage, not by filtering habitat
types; links from EFH items to habitat types, when used, are `supports function`, never
equivalences. Likewise, GOOS EOVs are observing variables, not habitat types: the habitats linked
to them (e.g. JNCC correlations) say which habitat types are used to map each EOV.

Every list is **generated by code from the official source files**, never typed by hand, so that it
is correct, traceable (each row has a `source`) and reproducible when a classification is updated.

## Tables (`data/processed/`)

| Table | Content |
|---|---|
| `systems.csv` | Catalogue of classification systems (name, version, authority, source, date). |
| `habitats.csv` | All habitats of all classifications, long format: system, code, name, level, parent, realm, group, description, source. |
| `crosswalks.csv` | Correspondences between classifications, with relationship type and source. |
| `lists.csv` | Catalogue of thematic lists (kind, version, authority, WP3 deliverable, source, status). |
| `list_items.csv` | Items of each list, with definitions (e.g. biogenic type `mussel-beds`, NRL group `G1-MED`, EOV `seagrass-cover-and-composition`). |
| `list_members.csv` | Habitats of any classification linked to each list item: region, biological zone, `link_type` (`member`, `partial`, `supports function`, `excluded`), `status` (`published`, `proposed`, `reviewed`, `rejected`), who decided, source. |
| `templates/*.csv` | Attribute table templates of the EMODnet habitat maps (DEF) and of the WP3 composite products, compiled from the product reports, with a field × template matrix (see `docs/templates.md`). |
| `extraction_rules.csv` | Data source and query used to extract polygons for each list item, by region (as published). |
| `eov_seagrass_filter.csv` | One row per habitat (system, code) of `EOV_SEAGRASS`: the link used to filter the map library (`use` = `yes` / `partial` / `broader` / `no`), its item, sources and what to review. |

Column definitions: [`docs/schema.md`](docs/schema.md).

## Scripts

| Script | What it does |
|---|---|
| `scripts/composite_eov.py` | EOV polygon composite from the map library (test, D3.03): selects the polygons of the items of a product filter (`HAB_TYPE` / `ORIG_HAB` codes with provisional class aliases, or text), repairs and snaps geometries to the INSPIRE 1 m grid (EPSG:3035), resolves overlaps tile by tile (INSPIRE 10 km cells from `standardgrid`; rank = source priority, `SUM_CONF`, date), writes the EOV polygon template plus provenance fields, an INSPIRE 1 km cover grid and a comparison with the 2025 composite. Needs geopandas, shapely 2, pyogrio, standardgrid. |
| `scripts/inventory_maplibrary.py` | Inventory of the map library shapefiles (DEF): reads only the `.dbf` attribute tables (Python standard library), writes `maps.csv`, `class_values.csv` (input of `class_aliases`), `habitat_values.csv` and, with `--filter data/processed/eov_seagrass_filter.csv`, `candidates.csv`. |

### Lists

Each list has a `role` in `lists.csv`: **`objective`** when it is the list of a WP3 deliverable (Updated Work Plan 2025–2027), **`possible`** for the other lists, which could become a product (e.g. at a stakeholder's request, D3.09) but are not objectives of the project. `GOOS_EOV` and `NRL_2024_MARINE` are also references of objective lists (EOVs; D3.08).

## Usage

```bash
pip install -e ".[dev]"
ehl-build --sources "path/to/classification systems"   # writes data/processed/*.csv
pytest
```

The source files are not part of the repository: see [`docs/sources.md`](docs/sources.md) for
the folder layout, references and links. PDF sources need `pdftotext` (poppler-utils).

The EUNIS habitats are read directly from the `eunis_habitats.rda` file of the R package
[`{eunis.habitats}`](https://github.com/ramiromagno/eunis.habitats) (downloaded and cached in
`data/raw/`), so Python and R users share the same codes and system ids
(`EUNIS_2012`, `EUNIS_M_2019`, `EUNIS_M_2022`, `EUNIS_T_2021`). 90 empty rows present in that
table are dropped.
